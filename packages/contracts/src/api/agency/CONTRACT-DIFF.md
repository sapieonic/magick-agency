# Core contract vs console wire shapes — what the merged API must reconcile

`../../agency.ts` is core's frozen contract (`magic-voice-core/src/agency/contracts.ts`
@ `4850d1d9`). The files in this directory are what the console was compiled
against (`magick-comms-cusui/src/types/*` @ `ee5beb44`), i.e. what master served
**after** enriching core's payloads. Where a name exists in both, the two are not
interchangeable: the Phase 8 API has to pick one shape per route and either
produce the enrichment itself or drop it from the console.

Generated by walking both ASTs (member name + declared type text), then read by
hand. "Identical" means same member names, optionality and type text.

## 4. Console-only shapes with no core counterpart in `contracts.ts`

These are master's own surfaces or core shapes declared outside `contracts.ts`;
the merged API owns them outright: the campaign object (`AgencyCampaign`, core's
lives in `src/api/responses/agency-campaign.response.ts`), ingest
(`AgencyIngest*`, `AgencyUploadResponse`, `AgencyColumn*`), retry policy
(`AgencyRetryOutcome`/`Policy`/`Rule`), `AGENCY_RETRY_REFUSAL_CODES`, staffing
(`AgencyMyAssignment(s)`, `AgencyAssignment`, `AgencyAssignedAgent`,
`AgencyAgentAssignment`, `AgencyStaffingHistory*`), `*WithName` roster/group rows,
activity (`agency-activity.ts`), DNC (`dnc.ts`), analysis profiles
(`call-analysis-profile.ts`), and the call detail (`webrtc-call.ts`,
`attempt-call.ts`).

## 5. Things the merge should NOT carry over

- `agent_user_id` as a request field (`AgencyCreateSessionRequest`, `AgencyActorFields`)
  was "master's fact" on the S2S hop. In one app the server derives it from the
  session; it remains in `agency.ts` only because core's runtime parses it
  (candidate deletion, see `PORTING.md`).
- `on_behalf` likewise becomes a server-side decision from `agency.supervise`.
